# 初期部署与联调环境

以下为起步工程估算，不是经过压测的容量承诺。不需要现在购买多台服务器。

## 建议提供的 VPS

| 项目 | 建议 |
|---|---|
| 系统 | Ubuntu 24.04 LTS，x86_64 |
| CPU / 内存 | 4 vCPU / 8 GB RAM |
| 磁盘 | 80 GB SSD；若长期保留构建缓存与产物建议 120 GB |
| 网络 | 公网地址，可通过 HTTPS 访问实际 XBoard 和构建依赖源 |
| 入口 | API 域名，例如 client-api.你的域名；可另配 admin 子域名 |
| 访问 | SSH 普通部署用户，具备安装服务所需 sudo 权限 |
| 端口 | 443；80 用于 HTTPS 跳转/证书签发；SSH 限制管理来源 |

这台机器初期运行 API、worker、后台、PostgreSQL、Redis 与 TLS 反向代理。
数据库和 Redis 仅在内部网络开放。它不转发用户的代理流量，节点继续由现有面板管理。
带宽需求取决于配置大小、同步频率与安装包分发；安装包后续可移至对象存储/CDN。

若已有 Linux 构建机，仅运行少量测试用户的联调服务，可先用 2 vCPU / 4 GB / 40 GB。
若构建与服务共机，限制构建并发，正式运营后拆分 CI，避免编译挤占数据库资源。
上线前需要备份、恢复演练、证书续期与按目标并发进行压测。

## 请提供的信息

1. XBoard 版本、仓库地址或所用分支；面板 HTTPS 域名。
2. 一个普通测试账号，包含可用于验证的测试套餐/订阅；不需要管理员账号密码。
3. 自定义 WebSocket 的协议说明（如有）：认证方式、事件示例、心跳与重连规则。
4. VPS IP、SSH 端口、用户名及本机 SSH 配置名称或密钥路径。
5. 可用于 API/后台的域名及 DNS 是否可修改。
6. 首批预计活跃用户、在线设备、每账号设备上限，以及期望离线宽限时长。

账号和服务器密钥放在本机 `.private/` 或已有 SSH 配置中，不写入设计文档或 Git。
仅提供路径即可。真实面板适配在获取上述信息后进行，不假定某个公开 XBoard 分支
与生产面板的登录、订阅或 WS 行为一致。

## Linux 验收环境

无桌面的 VPS 可负责后端联调与 Linux 编译；桌面 UI、托盘、权限提示及实际 TUN
仍需要 Linux 桌面虚拟机或实体机测试，不能用 HTTP 测试替代。
